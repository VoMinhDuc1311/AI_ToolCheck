### 2. Luồng hoạt động chi tiết (Hệ thống phân tích mã nguồn bằng AI)

Hệ thống có một luồng chạy Bất đồng bộ (Asynchronous) để tránh làm treo server khi chờ AI xử lý (Gemini xử lý code có thể mất từ 10s - 30s). Dưới đây là luồng đi của dữ liệu từ lúc User bấm nút đến khi ra kết quả:

#### Bước 1: Tiếp nhận dữ liệu (Synchronous - Phản hồi ngay lập tức)
1. Frontend gửi file code Legacy (Java) hoặc thông tin Project lên qua `SourceFileController` / `SourceProjectController`.
2. Controller gọi xuống `SourceFileService` để lưu thông tin file thô vào Database.
3. Hệ thống sử dụng package `service/analysis` (vd: `JavaSourceAnalyzer`) để quét sơ bộ file code xem nó thuộc loại gì (Servlet, Controller, Utility, Entity...) và đánh giá xem file này có đáng để gọi AI hay không.

#### Bước 2: Đưa vào hàng đợi xử lý ngầm (RabbitMQ Producer)
1. Nếu file được xác định là cần bóc tách API, hệ thống sẽ tạo ra một bản ghi `AiJobLog` trong Database với trạng thái `PENDING` (Chờ xử lý).
2. `AiTaskProducer` (trong package `rabbitmq`) sẽ đóng gói ID của file, loại Skill AI cần dùng (AI Skill 0) thành một Message và đẩy vào hàng đợi RabbitMQ.
3. Controller lập tức trả về cho Frontend ID của Job (HTTP 202 Accepted). Frontend không phải chờ đợi mà có thể dùng ID này để hiển thị loading (polling/websocket) cho User.

#### Bước 3: Tiêu thụ và gọi AI (RabbitMQ Consumer & Gemini Service)
1. Ở dưới nền (Background Thread), `AiTaskConsumer` liên tục lắng nghe hàng đợi. Khi có Message mới, nó bốc ra xử lý.
2. Nó cập nhật trạng thái của `AiJobLog` trong DB thành `RUNNING`.
3. `AiTaskConsumer` lấy mã nguồn từ DB và gọi sang `GeminiApiClientServiceImpl`.
4. Tại đây, `GeminiApiClientServiceImpl` sẽ nhúng Master System Prompt (Luật phân tích) + JSON Schema + Mã nguồn cũ, sau đó gửi yêu cầu POST đến Google Gemini API qua cấu hình WebClient.

#### Bước 4: Nhận kết quả và Lưu trữ
1. Gemini trả về một cục JSON chuẩn chỉ. `GeminiApiClientServiceImpl` dùng ObjectMapper để parse JSON này thành đối tượng Java (`AiInferenceResultDto`).
2. `AiTaskConsumer` nhận lại đối tượng này. Nó tiến hành lưu các thông tin bóc tách được (Tên API, Path, Method, Parameters...) vào các bảng `ApiEndpoint`, `ApiParameter` trong Database thông qua các Repository.
3. Cuối cùng, cập nhật trạng thái của `AiJobLog` thành `SUCCESS` (hoặc `FAILED` nếu Gemini API lỗi/timeout và ghi lại log lỗi).

#### Bước 5: Cập nhật Frontend
1. Frontend (đang định kỳ gọi API lên `AiJobLogController` để check ID) sẽ thấy trạng thái đã chuyển sang `SUCCESS`.
2. Frontend gọi tiếp API để lấy danh sách `ApiEndpoint` vừa được phân tích ra màn hình để hiển thị cho User.

**Tóm tắt ngắn gọn nhất:**
Frontend ➜ Controller ➜ Lưu file DB ➜ Tạo Job PENDING ➜ Đẩy vào RabbitMQ ➜ Trả ID ngay cho FE ➜ RabbitMQ Consumer bốc Job ➜ Đổi trạng thái RUNNING ➜ Gọi Google Gemini API ➜ Ép trả JSON ➜ Lưu API Endpoints vào DB ➜ Đổi trạng thái SUCCESS ➜ Frontend lấy kết quả hiển thị.
